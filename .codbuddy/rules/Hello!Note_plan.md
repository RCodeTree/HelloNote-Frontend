# Hello!Note 个人笔记网站项目规划书

项目名称：Hello!Note

## 一、项目概述

### 1.1 项目名称

Hello!Note —— 个人笔记与 AI 知识管理系统

### 1.2 项目目标

Hello!Note 是一个个人笔记管理网站，初期主要实现笔记的创建、编辑、删除、查询和分类管理等基础功能。

在完成基础功能后，逐步加入云存储、AI 智能总结、语义搜索、RAG 知识库问答以及 Agent 自动化操作等功能。

项目不仅是一个笔记网站，也是一个用于学习和实践以下技术的完整项目：

- Python 与 FastAPI 后端开发。
- Vue 3 前端开发。
- MySQL 数据库设计与管理。
- 前后端分离开发。
- Docker 容器化部署。
- AI 大模型、RAG 和 Agent 应用开发。

### 1.3 项目开发原则

1. 采用前后端分离架构。
2. 前端和后端使用两个完全独立的 Git 仓库。
3. 先完成基础笔记功能，再逐步扩展。
4. 代码结构清晰，尽量采用分层设计。
5. 暂时不引入不必要的复杂技术。
6. 后续功能尽量复用已有业务代码，避免重复开发。

## 三、项目目录结构

### 3.1 本地工作区

整个项目在本地使用一个工作区目录管理，但是前端和后端分别维护自己的 Git 仓库。

```
Hello!Note/
│
├── HelloNote-Backend/       # 后端项目，独立 Git 仓库
│
└── HelloNote-Frontend/      # 前端项目，独立 Git 仓库
```

这里需要特别注意：

- `Hello!Note/` 只是本地工作区，不初始化 Git。
- `HelloNote-Backend/` 单独初始化 Git，配置后端远程仓库。
- `HelloNote-Frontend/` 单独初始化 Git，配置前端远程仓库。
- 前后端分别提交、推送和管理版本。
- 不使用一个 Git 仓库同时管理前后端。

这样可以让前后端独立开发、独立部署，也方便未来进行维护。

## 四、后端架构设计

### 4.1 分层架构

后端采用分层设计，将不同功能放在不同目录中，降低代码之间的耦合程度。

| 目录              | 主要职责            | Spring Boot 对应概念    |
| --------------- | --------------- | ------------------- |
| `main.py`       | 创建 FastAPI 应用   | 启动类                 |
| `api/`          | 接收 HTTP 请求、返回响应 | Controller          |
| `schemas/`      | 请求和响应数据校验       | DTO                 |
| `services/`     | 处理业务逻辑          | Service             |
| `repositories/` | 数据库查询和操作        | Repository / Mapper |
| `models/`       | 定义数据库模型         | Entity              |
| `db/`           | 数据库连接和会话管理      | 数据源配置               |
| `core/`         | 项目配置、安全等公共功能    | Configuration       |

### 4.2 请求处理流程

```
前端 Vue 3
    │
    │ HTTP 请求
    ▼
API 接口层
    │
    │ 接收请求
    ▼
Schemas 数据校验
    │
    │ 校验通过
    ▼
Service 业务逻辑层
    │
    │ 调用数据库操作
    ▼
Repository 数据访问层
    │
    ▼
MySQL 数据库
    │
    │ 返回数据
    ▼
Service 处理结果
    │
    ▼
API 返回 JSON
    │
    ▼
前端展示数据
```

### 4.3 重要概念区分

初学 FastAPI 时，需要重点理解以下几个部分：

- `models/`：描述数据库中实际保存的数据结构。
- `schemas/`：描述接口接收什么数据、返回什么数据。
- `services/`：处理具体业务规则。
- `repositories/`：负责数据库查询、添加、修改和删除。

例如，用户创建一篇笔记：

1. 前端提交标题和正文。
2. API 接收请求。
3. Pydantic Schema 校验数据。
4. Service 处理创建笔记的业务逻辑。
5. Repository 将数据写入 MySQL。
6. API 将创建结果返回给前端。

## 五、数据库设计规划

### 5.1 初期核心数据表

初期先围绕笔记管理功能设计数据库，不要过早增加复杂的数据表。

| 数据表           | 主要用途    | 优先级  |
| ------------- | ------- | ---- |
| `users`       | 用户信息    | 后续   |
| `notes`       | 笔记信息    | 必须   |
| `tags`        | 标签信息    | 第二阶段 |
| `note_tags`   | 笔记与标签关联 | 第二阶段 |
| `attachments` | 附件元数据   | 后续   |

### 5.2 笔记表设计

初期的 `notes` 表可以包含以下字段：

| 字段名称         | 数据类型建议       | 说明   |
| ------------ | ------------ | ---- |
| `id`         | BIGINT       | 笔记主键 |
| `title`      | VARCHAR(255) | 笔记标题 |
| `content`    | TEXT         | 笔记正文 |
| `created_at` | DATETIME     | 创建时间 |
| `updated_at` | DATETIME     | 更新时间 |

后续可以根据需求增加：

- 笔记所属用户。
- 笔记状态。
- 笔记分类。
- 是否收藏。
- 是否置顶。
- 删除标记。

### 5.3 数据库开发要求

1. 使用 SQLAlchemy 2.x 操作 MySQL。
2. 使用 Alembic 管理数据库结构变化。
3. 数据库连接信息统一放在环境变量中。
4. 不在业务代码中随意创建多个数据库连接。
5. 不将数据库密码提交到 Git 仓库。

## 六、前后端通信设计

### 6.1 API 接口规范

统一使用 `/api/v1/` 作为后端 API 的版本前缀。

初期笔记接口规划：

| 请求方式   | 接口地址                 | 功能     |
| ------ | -------------------- | ------ |
| GET    | `/api/v1/notes`      | 获取笔记列表 |
| GET    | `/api/v1/notes/{id}` | 获取笔记详情 |
| POST   | `/api/v1/notes`      | 创建笔记   |
| PUT    | `/api/v1/notes/{id}` | 修改笔记   |
| DELETE | `/api/v1/notes/{id}` | 删除笔记   |
| GET    | `/api/v1/tags`       | 获取标签列表 |

### 6.2 前后端通信方式

- 后端使用 FastAPI 提供 REST API。
- 前端使用 Axios 发送 HTTP 请求。
- 前端统一在 `src/api/` 中封装请求。
- API 地址通过环境变量配置。
- 后端使用 CORS 配置允许前端访问。
- 开发阶段也可以使用 Vite Proxy 代理请求。

前端环境变量示例：

```
VITE_API_BASE_URL=http://127.0.0.1:8000/api/v1
```

后端启动后，可以通过 FastAPI 自动生成的 Swagger UI 调试接口：

```
http://127.0.0.1:8000/docs
```

前后端不需要共享 Git 仓库，通过 API 接口约定进行协作即可。

## 七、项目功能规划

### 7.1 第一阶段：基础笔记管理

这是 Hello!Note 最初需要完成的核心功能。

| 功能   | 说明           |
| ---- | ------------ |
| 创建笔记 | 新建笔记，填写标题和正文 |
| 查看笔记 | 查看笔记列表和详细内容  |
| 编辑笔记 | 修改已有笔记       |
| 删除笔记 | 删除不需要的笔记     |
| 搜索笔记 | 根据标题或正文关键词搜索 |
| 时间记录 | 记录创建时间和更新时间  |

### 7.2 第二阶段：完善笔记管理

在基础功能稳定后增加：

- 用户登录和身份认证。
- 用户个人笔记管理。
- 笔记分类。
- 标签管理。
- 笔记分页。
- 收藏和置顶。
- 更完善的搜索功能。
- 异常处理和日志记录。

### 7.3 第三阶段：附件与云存储

支持笔记上传图片、文档等附件。

初期可以使用本地文件存储，后续再迁移到云对象存储。

建议采用以下结构：

```
笔记业务 Service
      │
      ▼
文件存储 Service
      │
      ▼
文件存储接口
      │
      ├── 本地文件存储
      │
      └── 云对象存储
```

数据库只保存附件元数据，例如：

- 文件名称。
- 文件类型。
- 文件大小。
- 所属用户。
- 对象存储键。
- 上传时间。

不建议直接将图片、文档等大文件存放在普通笔记正文中。

### 7.4 第四阶段：AI 智能功能

逐步为 Hello!Note 加入 AI 能力。

| AI 功能   | 说明         |
| ------- | ---------- |
| AI 笔记总结 | 自动总结笔记内容   |
| AI 标题生成 | 根据正文生成合适标题 |
| 关键词提取   | 自动提取笔记关键词  |
| 智能标签    | 根据内容推荐标签   |
| 语义搜索    | 根据自然语言查找笔记 |
| 多笔记总结   | 对多篇笔记进行归纳  |

### 7.5 第五阶段：RAG 知识库

将个人笔记逐步发展为可以进行智能问答的知识库。

基本流程：

```
用户笔记
    │
    ▼
文本分块
    │
    ▼
Embedding 向量化
    │
    ▼
向量数据存储
    │
    ▼
用户提出问题
    │
    ▼
检索相关笔记
    │
    ▼
组织上下文
    │
    ▼
调用大语言模型
    │
    ▼
返回回答及笔记来源
```

后续可以考虑：

- 向量数据库。
- Embedding 模型。
- 文本分块策略。
- 相似度检索。
- RAG 检索增强生成。

初期不需要提前确定向量数据库，等到实际开发 RAG 功能时再进行选择。

### 7.6 第六阶段：Agent 自动化能力

在基础 AI 和 RAG 功能稳定后，再考虑引入 Agent。

未来 Agent 可以具备以下工具：

| 工具   | 功能           |
| ---- | ------------ |
| 搜索笔记 | 根据关键词搜索笔记    |
| 读取笔记 | 获取笔记完整内容     |
| 创建笔记 | 根据用户要求创建笔记草稿 |
| 修改笔记 | 修改已有笔记       |
| 查询标签 | 获取已有标签       |
| 总结笔记 | 对一篇或多篇笔记进行总结 |

Agent 的基本工作流程：

```
用户提出需求
    │
    ▼
Agent 分析任务
    │
    ▼
选择对应工具
    │
    ▼
调用后端 Service
    │
    ▼
执行具体业务
    │
    ▼
返回执行结果
```

开发注意事项：

1. Agent 不应该直接绕过业务层操作数据库。
2. 所有工具调用都需要进行权限检查。
3. 修改、删除等重要操作应根据风险要求用户确认。
4. 尽量复用现有 Service，不要重复编写业务逻辑。

- Python 虚拟环境。
- pip 或其他 Python 依赖管理工具。
- FastAPI 基础。
- Vue 3 基础。
- TypeScript 基础。
- Vite 基础。
- Git 基础操作。

阶段目标：

前后端能够独立启动、独立运行、独立提交和推送。

2. 学习 SQLAlchemy 2.x。

### 第四阶段：开发前端网站

主要任务：

## 十、项目开发注意事项

### 10.1 不要过早增加复杂技术

项目初期重点是：

- FastAPI。
- Vue 3。
- MySQL。
- SQLAlchemy。
- 基础 CRUD。

暂时不需要引入：

- Redis。
- Celery。
- Kubernetes。
- 向量数据库。
- Agent 编排框架。
- 复杂微服务架构。

等到实际需求出现后再考虑。

### 10.2 注意敏感信息管理

以下内容不能提交到 Git：

```
.env
数据库密码
JWT 密钥
AI API Key
云存储密钥
其他敏感配置信息
```

应该提供 `.env.example`，只保留配置项名称和示例值。

### 10.3 保持后端分层清晰

尽量避免把所有代码都写在 `main.py` 中。

例如：

- API 只负责处理 HTTP 请求。
- Schema 负责数据校验。
- Service 负责业务逻辑。
- Repository 负责数据库操作。

### 10.4 AI 功能尽量复用现有业务层

例如，AI Agent 创建笔记时，应该调用已有的笔记 Service，而不是重新编写一套数据库操作逻辑。

这样可以减少重复代码，也能统一权限检查和业务规则。

## 十三、项目最终目标

Hello!Note 的最终目标不是简单实现一个笔记增删改查网站，而是通过持续开发，将其逐步发展为一个具备以下能力的个人知识管理系统：

1. 基础笔记管理： 支持笔记创建、编辑、删除、查询和分类。
2. 数据管理： 使用 MySQL 保存数据，支持稳定的数据持久化。
3. 文件管理： 支持图片、文档和其他附件上传，逐步接入云存储。
4. AI 智能处理： 支持笔记总结、标题生成、关键词提取和标签推荐。
5. 知识库检索： 利用 RAG 实现基于个人笔记的智能问答。
6. Agent 自动化： 让 AI 能够根据用户需求搜索、读取、创建和整理笔记。
7. 项目部署： 使用 Docker 等技术完成部署，具备长期运行和维护能力。

最重要的开发思路：先完成一个真正能用的 Hello!Note，再通过真实需求逐步学习和引入新技术。不要为了使用技术而增加技术，始终让技术服务于项目功能。
